# 欄位權威性與計算邏輯盤點

## 文件狀態

- 狀態：field-lineage source；逐份責任裁決見 `document/架構重整/03_追蹤清單與證據/evidence/field_authority_review_v1.md`，不覆蓋正式 SSOT。
- 範圍：`db/schema.sql` 與 `db/schema_parts/*.sql` 中可辨識的資料表、欄位及外鍵。
- 用法：先建立完整骨架，再逐欄確認權威來源、公式、命令、狀態機與凍結邊界。
- 限制：初版只記錄 schema 宣告；live writer、API 與 UI 漂移會在逐欄核對時補入。

## 欄位分類

| 分類 | 定義 |
|---|---|
| 來源事實 | 由人員、外部事件或正式命令提供，不能由其他投影反推 |
| 衍生投影 | 可由更基礎事實重算，不具獨立業務權威性 |
| 不可變快照 | 跨越財務或稽核邊界後保存當時計算依據 |
| 工作流狀態 | 表示命令、人工審核或處理流程的階段 |
| 領域狀態 | Aggregate 的正式生命週期結果 |
| 稽核／關聯 | 保存版本、操作者、原因、冪等與 lineage |
| 待分類 | 尚未逐項裁決 |

## 已確認的全域帳務核銷規則

- 適用範圍：訂金、頭款、尾款、共用財務調整、補助退還、月嫂一般應付、樓層費、月嫂調整及其他正式應收／應付義務。
- 原始銀行流水不論金額是否正確，均先保存在 `finance_import_rows`；此層是外部金流事實，不等於已核銷的正式交易。
- 核銷 Preview 可同時選取一筆或多筆原始流水及一筆或多筆同方向義務，但 Apply 前必須同時滿足：
  - 每一筆所選金流均被完整分配，未分配差額為 0。
  - 每一筆所選應收／應付義務套用後餘額均恰好為 0。
  - 不得跨越業務上禁止互抵的義務邊界；訂金、頭款、尾款仍各自獨立核銷。
- 任一條件不成立即整批禁止建立正式交易與分配；原始流水留在匯入層並觸發財務異常／人工處理。正式帳本不保存部分核銷或未分配中間狀態。
- 多筆原始流水可在同一次核銷 Apply 中共同結清一筆義務；一筆原始流水也可透過 M:N 分配同時結清多筆允許合併處理的義務。Apply 必須是全有或全無的原子寫入。
- 同一次原子核銷的所有 `finance_import_rows` 共用同一個 `reconciliation_reference`，作為核銷 Apply 的共同識別與冪等關聯；不另建核銷批次表。此 reference 不參與金額計算，正式交易仍各自以 `finance_import_row_id` 指回原始流水。
- 2026-08-02 後項裁決已否決人工月結與即時計算月結文件模型：業務維持 `staff_payments` 應付投影、應付款清單與 Excel 匯出，不建立 draft／finalized／revision／paid 月結狀態機。同一月嫂同一付款月份的多訂單在查詢／匯出時依 `staff_id` 合併；現有 `staff_monthly_settlements` 相關表與 caller 只作歷史相容，遷移完成前不刪除，新架構不得再依賴。
- 月嫂基本應付日期的唯一血緣為：訂單完成日與客戶付款類型 → 訂單層正式 `staff_payment_due_date`。客戶有服務費應付時為完成後次月 15 日；客戶服務費為 0 且政府全額補助時為完成後次次月 15 日。取消或實際服務日更正後沿用原訂單應付日，不自動改期；原日已過才形成或改變義務時進入異常中心。
- 只有有效銀行出款淨額使本次完整應付義務精確歸 0，才能由「應付」轉為「已完成」。不足額、超付、部分付款或金額不符只留在匯入／異常層，不形成正式中間狀態。已發生正式出款後的更正以 adjustment／reversal 保存不可變歷史。
- 每次下載應付款 Excel 都保存與使用者取得完全相同的 bytes 至 `downloads/accounts_payable_archive/YYYY/`；XLSX 本身是當次輸出快照，不另建月結或下載快照表。下載不改變付款狀態。

## 已確認的跨表原則

- `case_staff_assignments.actual_hours`：衍生投影／可重建快取；權威來源為 assignment-owned 正式工作日。
- `orders.actual_end_date`：衍生投影；由全案有效 assignment-owned 正式工作日最大日期推算。
- 案件服務資料鎖成立前的排班修改：取消目前有效 assignments，依 Preview 建立新 assignments 與正式服務日。全案條款變更重建全案；局部請假／順延／代班只重建受影響 family，但皆驗證全案守恆。
- 案件服務資料鎖只在「訂單完成＋客戶正式應付款全部結清」兩者同時成立後建立，且成立後不可逆；後續收款沖正或退款只重開／調整帳務，不恢復一般服務資料重建。
- 中途取消的樓層費先依全案實際服務天數縮減，再依各 assignment 實際服務日分配；全部金額為整數元，最大餘數法處理尾差，客戶已認列樓層費與月嫂 assignments 分配合計必須相等。
- 客戶端與月嫂端分別核銷後各自餘額必須精確為 0；未打平不得標示完成。

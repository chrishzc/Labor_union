# 異常代碼偵測位置與寫入路徑對照表

> **建立時間**：2026-08-09
> **適用範圍**：異常警示中心（`ui/pages/06_finance_alerts.py`）所讀取的 canonical 異常註冊表 `anomaly_current_alerts`
> **對應程式**：`domains/anomalies/registry.py`（異常定義目錄）＋ 各 `subsystems/anomalies/*.py`／`infrastructure/mysql/*_anomaly_source.py`（實際偵測規則）

本表列出目前 `default_anomaly_registry()` 註冊的全部異常代碼，說明每個代碼的偵測時機（事件觸發同步偵測，或背景迴圈定期重新掃描）與資料寫入路徑（直接寫進 canonical，或先經過中繼表再由背景迴圈投影）。

## 判斷原則

- **事件觸發型**：偵測附著在一個跟異常系統無關的業務交易上（例如匯入 Excel 某一列、分類某一筆銀行交易）→ 先寫進中繼表，讓業務交易本身不被異常寫入的失敗拖累，異常寫入可交由背景迴圈之後重試。
- **狀態掃描型**：偵測本身就是背景迴圈定期主動重新計算現況（例如「現在有沒有月嫂檔期重疊」），沒有依附任何業務交易 → 直接寫進 canonical，不需要中繼表這層緩衝。

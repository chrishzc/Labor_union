# G05：服務完成時刻與請假／代班競爭契約

## 現況裁決

`lifecycle_authoritative_facts_loader` 已能從正式服務日、`actual_end_date`、
服務時間與 Asia/Taipei clock 推導 `auto_complete` 是否可成立；但它目前只是
唯讀判斷，沒有對應的 Orders typed Apply。任何以 legacy 直接更新
`orders.status` 來補足這段流程，都會繞過 version、idempotency、audit、outbox 與
請假／代班的跨 Domain 交易邊界，禁止採用。

## 正式 command

`AutoCompleteOrderService` 是 Orders Domain 唯一可將服務完成時刻持久化的 command。

- input：`case_no`、expected Orders lifecycle version、evaluation instant（Taipei）、
  idempotency key、actor、reason、correlation id；
- root facts：locked Orders lifecycle envelope、assignment-owned official service days、
  effective scheduling generation、service time terms、active lifecycle controls；
- decision：只有 `evaluation_at >= completion_instant`、正式服務日完整、沒有
  `auto_complete` blocker 且非取消／已完成狀態時，才由 `服務中` 轉為 `訂單完成`；
- persistence：同一 Orders UoW 追加 immutable lifecycle event、樂觀版本更新、
  idempotency receipt 與 post-commit Orders source outbox；不重建或結清 Client Finance、
  Payroll、退款或補助義務；
- replay：同 key、同 command fingerprint 回原 receipt；payload mismatch 為 typed
  idempotency error；expected version／fingerprint 漂移為 typed conflict；
- blockers：時刻未到、服務日不完整、資料矛盾、human hold 或取消均為 typed
  `domain_blocked`，零寫入。

## 與請假／代班的競爭不變量

請假／代班 Apply 與 AutoComplete 都必須先鎖定同一 Orders lifecycle aggregate。

1. 若 AutoComplete 先提交，leave Preview 的 Orders version 已 stale；leave Apply 必須
   typed conflict，且不得產生 scheduling generation、Client Finance、Payroll、outbox 或
   leave outcome 寫入。
2. 若 leave／代班先提交，必須先更新服務日與 Orders lifecycle version；舊 completion
   Preview／command 必須 typed conflict。重新以新的服務日計算的 completion instant 才可
   再判斷是否完成。
3. 兩者不能以「先完成後再補請假」或「自動以舊日期完成」隱藏競爭；人工後續更正須由
   獨立、可稽核的 correction command 處理。

## G05 驗收

隔離 `lu_test_*` MySQL E2E 必須至少涵蓋上述兩個順序，並驗證 locked row、typed error、
idempotency receipt、lifecycle／scheduling／finance／payroll／outbox 的精確 before/after
counts。不得使用 `union_db`、mock transaction 或 legacy `orders.status` writer。

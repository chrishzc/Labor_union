## 2. 帳務差額處置與更正模式

<a id="finance-differences"></a>

### 2.1 差額事實與人工處置選項（`DIFF-*`）

- **極簡操作互動**：前台 `FinanceCaseAccounting` 自動判定呈現四種客觀差額事實：**少收**（實收 `<` 應收）、**多收**（實收 `>` 應收）、**少付**（實付 `<` 應付）、**多付**（實付 `>` 應付）。人員選擇處置方向並填選填原因；支出 `0 <= 差額 <= 100` 依 [支出核銷規則](22_銀行流水匯入與帳務異常處理正式規格.md#outgoing-statement-fee-reconciliation) 直接以手續費結清。
- **`DIFF-CHOICE-01`（無預設選項）**：人工差額處理絕不預選任何處置或自動套用，須待人員主動選取後方執行；原精確自動核銷維持不變。

| 需求 ID / 子選項 | 處置操作與核心邊界 | 處理後狀態與資料保留 |
|---|---|---|
| `DIFF-CORRECT-01` | 核查系統應收／應付有誤後手動更正（保留計算與人工更正記錄）；已核銷款「保留原核銷，另列更正差額」 | 更正後重對，非已收付 |
| `DIFF-RECEIVE-01` / `PAY-01` | 少收／少付超過 100 元核銷實收／實付並保留原義務餘額待續收補付；政府少撥見 [Government Subsidy](14_Government_Subsidy_Domain.md#21-整期狀態與防重不變量gov-status-01) | 部分已收／已付＋剩餘待處理 |
| `DIFF-REFUND-01` / `RECOVER-01` | 多收另列退款、超付另列追償（全額保留銀行原事實） | 原款已清＋待退／待追回 |
| `DIFF-LOSS-01` | **確認收不回，記錄損失**（適用客戶欠款、超付追償與政府少撥，記在人員實際確認處理月份） | **已作損失處理**；銀行原實收付與原欠款保留 |
| `DIFF-REDUCE-01` | **同意減收服務費**（只減客戶應收，差額工會承擔；**嚴禁連動減月嫂薪資**；記於實際確認月份） | 餘額歸 0 時顯示 **已減收結清** |
| `DIFF-FEE-01` | **由工會負擔手續費**（限客戶存入淨額入帳，人員確認依據後記工會負擔且不改月嫂薪資；銀行另有獨立手續費列則沿該列計一次） | 餘額歸 0 時顯示 **已結清，工會負擔手續費** |
| `DIFF-ASSUME-01` | **工會承擔超付款，不再追回**（適用月嫂薪資多付與客戶退款多退追償，記於實際確認月份） | **已由工會承擔，不再追回** |
| `DIFF-CLOSE-01` | **確認不用再補付／退款**（**僅限客戶退款少退與多付款不用退回**；月嫂少付與政府款嚴禁使用） | **已結清**（原資料維持原樣，**不另存同意證明、免退明細或該次操作紀錄**） |
| `DIFF-HISTORY-01` | 歷史差額經確認無法查明之案件人工標記（排除實際金額統計，不改銀行原列或生命週期） | 案件標記保留原始差額與查核紀錄 |

- **簡化分類映射（UI 二選一）**：在簡化互動檢視中，將上述適用非現金認列／結清封裝為「**直接銷帳**（`settle_direct`，平帳歸零結清）」與「**認列差額**（`recognize_diff`，保留收付並記入確認月認列紀錄）」並配合各 owner guard 驗證；原交易退匯僅限同案抽屜人工選取有效原退款走 `refund-return` Preview／Apply。
- **追收協調（`DIFF-FOLLOWUP-01`）**：支持記錄追收／後期合繳安排；合繳入款按確認歸屬分配各期，通知由人員確認發送且不代替付款事實。

<a id="recalc-mode-and-case-total"></a>

### 2.2 人工金額更正與來源重新計算（`DIFF-RECALC-01`）

- 依款項當下「**自動計算／人工更正**」模式決定（非歷史修改痕跡）：
  1. **自動計算**：未人工更正或已明確採用新計算恢復者，來源變動後直接以最新計算結果更新。
  2. **人工更正**：手動更正金額後切換此模式，保留人工值並另列最新計算供人員確認，重整或重算絕不靜默覆蓋人工值。
  3. **恢復自動**：人員點擊「採用新計算結果」即採用新值並切回自動模式（原更正紀錄保留）；再次手動改值始切回人工模式。受保護之已核銷／政府快照維持不變，已收付差異走獨立差額／退款／追償。

### 2.3 同案多筆入款、永豐三階段核對與全案結清標示（`DIFF-CASE-TOTAL-01`）

- **同案多筆合計核對**：同案辨識之多筆銀行入款（例如分次補齊 `9,000 + 1,000 = 10,000`）於抽屜並列各筆原始明細與合計，合計相符即直接核銷，不得僅因單筆不同或有多期待收而誤報金額錯誤、疑似重匯或強設前置確認。
- **永豐客戶存入 3 階段與原因碼對齊**：依 [Client Finance §3.5](04_Client_Finance_Domain.md#35-專屬虛擬帳號與單案修改99781699va-0106) 依序驗證案件 → 金額唯一配對 → 交易日與到期日年月比對；當月多個候選統一回報 `sinopac_client_receipt_multiple_month_candidates`；缺日期回 `due_date_missing`／`bank_transaction_date_missing`；少收／超收沿 `client_receipt_underpaid`／`client_receipt_overpaid`（精確與部分收款不以退款帳戶為前置）。

<a id="client-receipt-scope-and-case-settlement"></a>

- **「本次期款核銷」與「案件所有應收結清」嚴格區分**：
  - **確認前預覽**：同一案件版本（版本不符阻擋確認）明列本次各選取期款名稱、到期日（缺設標未設定）、本次分配金額、核銷後該期餘額，以及「本次核銷合計」、「所選期款剩餘」、「其他未選期款待收」、「核銷後案件全部應收餘額」。全案預計餘額歸零時僅可顯示「**本次核銷後，案件所有應收餘額將歸零**」，尚有餘額時須明示尚有待收。
  - **正式成功回讀後方可宣告結清**：唯有正式 Apply 成功並以不舊於該收據之 account version 完成 Query 回讀，且全案所有應收及調整餘額均為 `0`，方可顯示「**案件已結清**」；部分收款／多收另退／其他期款未清皆須顯示案件尚有待收餘額。本狀態僅代表客戶應收已清，不等於月嫂付款、政府款、方案確認、Orders 結案或 `historical_accounting_completed`。

## 3. 帳務工作台四大主入口與精簡案件抽屜（`WF-01`～`WF-06`）

<a id="finance-six-surfaces-ui"></a>

### 3.1 導航結構、抽屜共用與狀態模型（`FIN-UI-NAV-01～02`、`DRAWER-*`）

- **主導航收斂**：`#finance` 固定提供四大頂層工作區——**進行中案件（預設，`WF-01`）**、**銀行對帳（`WF-03`）**、**政府補助清單（`WF-05`）**、**每月帳務（`WF-06`）**。帳務通知排程與 10 則 LINE 範本獨立置於左側一級選單「**帳務通知設定**（`#payment-reminder-settings`）」；入帳通知待辦由「**通知事項**（`#notifications`）」攜帶 `case_no` 深連結開啟 `WF-02`（含已移出進行中案件）；不設折疊二級選單。
- **統一抽屜（`WF-02`、`DRAWER-01～02`、`DRAWER-WIDTH-01`）**：任一工作區與深連結均開啟同一精簡右側案件抽屜（與客戶名冊同寬，手機全寬，內部水平捲動）；切換通知內容、人工方案設定或銀行核對皆於同抽屜返回並保留來源清單的搜尋、分頁、捲動、展開位置與鍵盤焦點（移出列後焦點退回搜尋／相鄰控制）。
- **畫面狀態（`STATE-01`、`DISPLAY-01`、`RESPONSIBILITY-01`）**：嚴格區分「載入中／空結果／讀取失敗（不補 0 或冒充尚未通知）／可操作／提交中／成功（回讀後刷新）／來源變更 409／結果未確認（保留原提交鍵與查詢）」；未儲存方案離頁受提示保護。

### 3.2 `WF-01` 進行中案件

- **納入與移出（`FIN-UI-WF01`、`ONGOING-01～03`、`REVIEW-01～02`）**：進入待辦看板第 8 步「訂金」即列入（含訂金未繳／部分繳）；當**客戶前三期全部繳齊（或免繳）且補助方案取得「人工明確保存」或「銀行明細 B 正式套用成功」**即自動移出。
- **固定 6 欄**：`案件／客戶`、`實際開始／結束日`（`DATE-01`：缺值標待確認不代填）、`相關月嫂`、`案件總額 T`（不以 `B` 或 `T - S` 替代）、`應操作／目前狀態`（依「訂金 → 第一期 → 第二期 → 設定補助退款方案」只列最早尚未完成事項與最近成功通知時間）、`操作`（「查看案件」＋發出提醒，共用抽屜通知來源；前三期已齊只剩方案時提醒按鈕灰色鎖定）。
- 人員可在前三期未齊時提前保存方案，且設定／修改依 [HANDOFF 交接規則](16A_Accounts_Payable_Export與現金需求清冊規格.md#manual-subsidy-plan-payables-handoff)（已到成立時點則先預檢並同交易由原 owner 承接款項）。

### 3.3 `WF-02` 精簡案件抽屜

- **補助款預計給付**：方案一顯示轉付月嫂，方案二顯示退還客戶。完工前以本案補助金額與預計服務結束月加兩個月的 15 日顯示預計金額、日期與收款對象。有目前有效的正式補助分期或退款時，逐筆顯示原義務金額、到期日及對象，未知日期保留待確認。無補助案件顯示「不適用」。預估為唯讀資訊，不形成應付、退款、待核銷項目或出款。

- **標頭與精簡摘要（`FIN-UI-WF02`）**：僅顯示一次案號與客戶，摘要列相關月嫂、實際開始日、實際結束日與 `T`。下方僅保留同頁兩個可展開區塊（無案件分頁、無重複金額大卡／全期差額卡／獨立歷史收付卡）：
  1. **客戶繳款（`COLLECTION-01` 固定 7 欄）**：`期款`（訂金／第一期／第二期，標明訂金含 `F`）、`原到期日`、`應繳`、`已收／待收`（實收與待收分列）、`入帳資訊`（僅顯示已核銷日期＋銀行或 `YYYY-MM-DD · 人工補登`，禁止預先暗示「另有銀行資料待核對」）、`通知時間`（僅取本期最後成功發送臺灣時間）、`通知`（`NOTIFY-01～05`：有效待收為 `0` 時灰色鎖定，部分收款正餘額可通知，未到期不額外禁發；發送前於同抽屜預覽對象、餘額、內容與近期紀錄）。取消結算案件另顯示「取消結算」區塊（`CANCEL-01`），提供應退／補收、已核銷與餘額回讀。
  2. **補助退款方案（`SCHEME-01`、`MEMO-01`）**：顯示獨立計算之 `S`、對象／來源狀態（未定／明細候選／人工保存／明細 B 確認）、[TAISHIN-MEMO-03](22_銀行流水匯入與帳務異常處理正式規格.md#43-台新補助出款備註辨識taishin-memo-0105) 原始台新備註原文，以及人工設定與預檢結果；抽屜內同時承接 §2.1 差額處置與 [§6 案件手動補登](22_銀行流水匯入與帳務異常處理正式規格.md#case-manual-accounting-supplement)。

### 3.4 `WF-03` 銀行對帳與 `WF-04` 核對子畫面

- 案件帳務的銀行帳戶摘要及退款／退匯核對子畫面顯示名冊登記的退款帳號及戶名，客戶退款列沿用同一登記帳號。完整值查閱依 [整合名冊退款帳號顯示契約](33_案件與月嫂整合名冊正式規格.md#53-客戶名冊欄位權威唯讀邊界與退款帳戶連動)。核對畫面標明名冊來源，銀行流水與正式退款快照仍各依原來源查閱。

- **`WF-03`（`FIN-UI-WF03`）**：提供永豐／台新匯入操作與獨立匯入紀錄、跨批去重查詢（交易日、方向、狀態、案號／對象／參考）、完整成功明細整庫匯出（見 [銀行流水匯入 §3.3](22_銀行流水匯入與帳務異常處理正式規格.md#33-成功明細整庫匯出bank-03)）。列表總待核對數與查詢範圍一致。
- **待核對標籤與下一步提示統一對齊**：依當次實際原因碼投影為三個固定標籤——**「金額不符」**（金額不符／少收超收／退款金額差額）、**「有多個候選款項」**（依規則比對後仍具多個有效配對）、**「待核對」**（缺交易日、缺到期日、幣別不符、舊概括紀錄未留細節或其他原因），禁止以泛用操作碼覆蓋已保存原因。
- **`WF-04`（`FIN-UI-WF04`）**：點「核對交易」於同一 `WF-02` 抽屜載入原流水並呈現「原始交易（唯讀）」、「歸屬確認」、「`C`」、「`R台`」、「`P永／P台`（含永豐方案一共同確認）」、「`R永／G`」及「確認與結果」；事前預檢擬建／沿用款項與核銷結果，提交失敗／未明保護原鍵；已核銷列轉唯讀；案件條件／取消／計價提交時跨分頁同步重查候選。

### 3.5 `WF-05` 政府補助清單與 `WF-06` 每月帳務

- **`WF-05`（`FIN-UI-WF05`）**：政府補助清單唯一入口，包含週報補助統計（原 14 欄，取迄日所屬完整年度＋`年度季度`）、季度補助（15 欄＋XLSX）、年度補助（10 欄＋XLSX）；營運週報僅留受理／工時與導向連結。切條件清舊下載，無效期間禁止匯出。
- **`WF-06`（`FIN-UI-WF06`、`MONTHLY-01`）**：選擇月份區間切換兩個口徑——**(1) 已核銷收付款**（按銀行交易日歸月，展開 `C／G／P永／P台／R永／R台` 與差額／違約金營收；政府直付不入工會現金，跨案整期不偽拆）與 **(2) 到期款進度**（按正式到期日歸月，區分未到期／到期／逾期／缺日期，跨月收付回原義務更新餘額）——並承接 **十欄會計應付 Excel 匯出** 與 **[歷史月嫂款未列入清冊查核](16A_Accounts_Payable_Export與現金需求清冊規格.md#historical-payables-review-entry)**。

## 4. 驗收標準

1. **`AC-DF01～DF20`**：驗證人工更正保留記錄、少收合繳、少付補付、多收退／超付追償、`DIFF-LOSS-01`／`DIFF-REDUCE-01`（不減月嫂薪資）／`DIFF-FEE-01`（淨額與另筆扣費不重複）／`DIFF-ASSUME-01`／`DIFF-CLOSE-01`（限兩類客戶款且不另存同意明細操作紀錄）、`DIFF-CHOICE-01` 無預設、`DIFF-RECALC-01` 往返切換、`GOV-STATUS-01`「已納入本期」至「已核銷」、同案多筆入款合計直接核銷，及退匯 `refund-return` 抽屜操作。
2. **`FIN-UI-A01～A36`**：驗證四主入口、同寬抽屜切換與鍵盤焦點復位、進行中 6 欄 4 階段入列與移出條件（含明細 B 與人工保存雙路徑）、抽屜兩區塊與 7 欄期款（無多餘卡片）、通知按鈕繳齊／免繳鎖定與同源時間、銀行 `WF-03/04` 預檢擬建款與三標籤原因一致、政府三報表匯出與月報雙口徑合計守恆。

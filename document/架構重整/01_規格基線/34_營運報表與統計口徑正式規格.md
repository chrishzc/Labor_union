# 營運報表與統計口徑正式規格

## 1. 範圍、權威與唯讀原則

本文件為營運作業四大報表與統計投影的唯一業務口徑與合約 SSOT，涵蓋：
1. **營運週報三分頁與 XLSX 匯出**（`operations-report.v4`，相容保留 `v3` 查詢參數：`週報案件受理總表`、`每週服務中與工時`、`補助案件統計表`）；
2. **補助資格分類、HCM 作廢與原住民統計口徑**（`QUAL-STAT-01`～`05`）；
3. **待辦看板單排案件統計與週報對齊**（`CASESTAT-01`～`06`）；
4. **非市民自費案件獨立統計**（`NC-STAT-01`～`08`）；
5. **月嫂表現分析**（`STAFF-PERF-01`～`05`，`staff-performance.v2`）。

- **唯讀與 Domain 歸屬不變量**：Reporting 為純唯讀投影與匯出子系統，除了明確受管之每週人力推廣／詢問指標外，不得建立或覆蓋任何 Orders、Client、Scheduling、Client Finance 或 Government Subsidy 根事實；補助額度與案件金額公式沿用 [`04_Client_Finance_Domain.md`](04_Client_Finance_Domain.md) 與 [`14_Government_Subsidy_Domain.md`](14_Government_Subsidy_Domain.md)，有效工作日沿用 [`02_Assignments_Scheduling_Domain.md`](02_Assignments_Scheduling_Domain.md)。
- **缺值不猜值原則**：歷史訂單缺欄位、未判定補助資格或無有效服務時間者，一律以 typed `null` 與明確 `data_quality_code` 保留列示，嚴禁於計算或呈現時以 `0` 或任意分類猜測遞補。

## 2. 營運週報三分頁契約（`operations-report.v4`／相容 `v3`）

### 2.1 期間邊界與公共介面

- **API 與權限**：唯讀查詢為 `GET /api/v1/operations-reports/weekly?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD`，完整活頁簿下載為 `GET /api/v1/operations-reports/weekly/export`（須標示 `start_date`/`end_date` 檔名，且僅匯出三張現行工作表；活頁簿內不含歷史 `113`/`114` 年頁）。
- **星期一分組不變量**：`start_date`／`end_date` 依 `Asia/Taipei` 雙端包含，且 `start_date <= end_date`。一週固定為**星期一至星期日**；跨週查詢一律按每個實際週一～週日邊界切分，嚴禁使用人工 week code、月內週數作為計算分組鍵（僅畫面「週數」欄可用 `月-第幾週` 如 `9-1` 作純標籤顯示）。
- **每週人工指標（Weekly Metrics）**：`PUT /api/v1/operations-reports/weekly/metrics/{week_start_date}` 以星期一為唯一主鍵獨立儲存「推廣次數」與「詢問人次」。`null` 代表未登錄，`0` 代表該週確實為零，兩者禁止混用且跨週不得擅自相加或綁定案件。舊參數 `week_start`、`promotion_count`、`inquiry_count`、`annual_ytd` 與年度週報路徑已全面退役。

### 2.2 三張分頁資料來源與輸出規則

|---|---|---|---|
| `週報案件受理總表` | `Clients` + `Orders`（正式案件依 `clients.created_at`；HCM 作廢紀錄依原申請／審核可追溯期間）；人工週指標 | 所選 `start_date`～`end_date` 週界；年度累計從 `1/1` 起至 `end_date` | 以雙層表頭呈現（25 欄 `A:Y`）：平台序號（`seq_num`）、年度月份、週報週數、申請人（去敏）、推廣次數／詢問人次（每週只列一次）、平台案件申請數、市民案件審核（一般市民符合／不符合）、社福案件審核（補助市民符合／不符合）、原住民案件審核（原住民符合／不符合）、申請案件狀況（訂單成立／洽談中／取消／審核不符合）、服務天數、每日時數、預計起訖日、服務狀況、區域（`東區`/`北區`/`香山`，缺時顯示地址）、備註。歷史狀態 `1`（「歷史訂單－未服務」）屬訂單成立（已付訂金）。XLSX 明細中互斥 `0/1` 旗標之 `0` 轉空白，推廣／詢問實際數值 `0` 保留。 |

## 3. 補助資格、HCM 作廢與原住民統計口徑（`QUAL-STAT-01`～`05`）

本節固定正式補助身分三軌：**一般市民**（原 rule 上限 40h）、**補助市民／社福**（原 rule 上限 120h）、**原住民**（含 HCM 來源別名 `原民`、`原住民市民` 正規化為 `原住民`，帳務參數設定，預設 80h／350 元）。嚴禁以單純名稱對照將一般市民與補助市民混同。

- **`QUAL-STAT-01` 去重原則**：同一案件申請唯一計數一次，且個案實務上不會同時具有多重補助資格（各案依唯一正式 `clients.identity_status` 歸類）。「六個資格欄」與「四個申請案件狀況欄」屬不同統計維度，嚴禁加總充當總件數。社福資格不符但符合一般市民資格者，最終適用身分歸「一般市民符合」，不列整案審核失敗且不重算兩筆案件，待確認者維持未定。
- **`QUAL-STAT-02` 「審核不符合」專義**：僅指整案補助資格審核不符合（來自 `clients.hcm_review_status = '不符合'` 獨立記錄）；單一社福不符合但一般市民符合、一般缺件或尚未建單皆不得推為整案「審核不符合」。其中一般原住民審查不符合（非屬非市民）計入「**原住民不符合**」。
- **`QUAL-STAT-03` HCM 作廢留存**：經確認實為非市民誤報（含以原住民或其他身分誤報者）之原 HCM 補助報名雖已作廢且禁止沿用或直接轉案，其「原申請紀錄與審核不符合結果」仍保留一次於週報「**一般市民不符合／審核不符合**」（維持原 `orders` 根狀態、不覆寫或刪除原紀錄）。
- **`QUAL-STAT-04` 自費轉號隔離**：非市民案件資料一律透過 [`17B_Case_Import與非市民Redis待審正式規格.md`](17B_Case_Import與非市民Redis待審正式規格.md) 專用 LIFF 頁面重新填寫（不得由 HCM 案件資料直接轉換），取得核准並配發 `A` 字頭正式自費案號後，依 §5 獨立統計計數，**不得回灌原 HCM 平台受理數與補助資格欄**，原 HCM 審核失敗結果亦不影響 `A` 案的服務執行。
- **`QUAL-STAT-05` 三端一致性與契約**：週報畫面、XLSX 匯出與待辦看板於相同期間共用同一資格與四欄統計口徑（API 沿用現行 `operations-report.v4` 直接補齊 `indigenous_eligible*`、`indigenous_ineligible*`、`review_result = indigenous_eligible` 與 `subsidy_partitions` 第三分區 `indigenous`）；實際帳務時數上限與計價由 [`04_Client_Finance_Domain.md`](04_Client_Finance_Domain.md) 與 [`14_Government_Subsidy_Domain.md`](14_Government_Subsidy_Domain.md) 擁有，Reporting 不得寫死 `80` 或自行計費。

<a id="case-statistics-alignment"></a>

## 4. 待辦看板案件統計與週報對齊（`CASESTAT-01`～`06`）

- **`CASESTAT-01` 單排呈現與維度隔離**：看板頂端採橫向單排顯示平台案件申請數、年度累計、三大補助資格群組共六欄（一般市民符合／不符合、補助市民符合／不符合、原住民符合／不符合）與模板四欄（訂單成立／洽談中／取消／審核不符合），另獨立區塊呈現 §5 非市民自費統計；下方既有 `in_progress` 待辦清單維持全量顯示，不受上方統計篩選影響。
- **`CASESTAT-02` 期間與累積邏輯**：只提供「年度、季度、月份」篩選（月份須屬於所選季度），依 `clients.created_at` 歸屬期間；頂端年度累計固定反應所選完整西元年度（`1/1`～`12/31`），不隨選取季度或月份縮小。
- **`CASESTAT-03` 一般／歷史狀態合併映射**：統計投影層將歷史狀態映射併入標準分類（`歷史未服務` → 訂單成立、`歷史服務中` → 服務中、`歷史服務完成／帳務完成` → 訂單完成），維持單一口徑而不設獨立歷史統計欄，亦不更改 Orders 根狀態。
- **`CASESTAT-04`～`06` API 與去敏**：呼叫 `GET /api/v1/operations-reports/case-statistics?year=YYYY[&quarter=1..4][&month=1..12]`，不回傳個資清單；回傳同時涵蓋模板四計數與原六種生命週期計數（`order_status_counts`）供非市民區塊使用。確認無不符合時回 `0`；存在未分類身分之不符合案件時相應欄位回 `null` 顯示缺值，嚴禁猜為 `0`。前端切換篩選須 abort 舊請求與忽略 late response。

<a id="noncitizen-statistics-20261029"></a>

## 5. 非市民自費案件獨立統計（`NC-STAT-01`～`08`）

- **`NC-STAT-01`～`03` 雙軌分流**：正式核准之非市民自費案件不納入補助案件受理統計（包括週報案件受理總表、看板補助統計），一律單獨呈現於「非市民案件統計」區塊，包含期間件數、年度累計與六種生命週期狀態（待補件／洽談中／訂單成立／服務中／訂單完成／訂單取消），不套用市民／社福／原住民六欄或補助金額欄位。原 HCM 非市民申請作廢紀錄仍維持列於 §3 審核不符合統計，兩者嚴格區隔。
- **`NC-STAT-04`～`05` 期間歸屬**：以**工會於 `Asia/Taipei` 正式核准建案日**作為歸屬年度／季度／月份之唯一基準；年底 LIFF 送出、隔年初核准者計入隔年，未核准待審單不計入任何統計。
- **`NC-STAT-06`～`08` 呈現與帳務邊界**：Reporting 查詢依正式案件類別區分統計口徑，不得僅在前端過濾或依賴 `A` 前綴猜測；帳務三方案與政府補助清單頁另依 [`04_Client_Finance_Domain.md`](04_Client_Finance_Domain.md) §2.1 提供補助案件／非市民案件／全部案件篩選，兩者互不取代。

## 6. 月嫂表現分析（`STAFF-PERF-01`～`05` / `staff-performance.v2`）

### 6.1 口徑與認列規則

- **`STAFF-PERF-01` 範圍與身分識別**：於營運報表提供月／季／年切換（對齊臺灣曆月／季／年；當期只計算至臺灣當日，前期比較取相同經過日數），可查全部或單一月嫂（含具歷史紀錄之退役月嫂），依 canonical `staff_id`、姓名與 nullable 公會自訂編號識別並依公會編號自然排序下拉選單，禁止僅以姓名合併識別。
- **`STAFF-PERF-02` 開案認列歸屬（單次認列原則）**：
  - 案件之**接案數（1 件）與整案金額只於該案 `Orders.actual_start_date` 所在月份認列一次，並僅歸屬於開案當下之主責月嫂**；後續月份及服務途中接手／代班之月嫂計入各自的服務工時與服務月嫂人數，**接案數與本期認列金額均為 `0`**，嚴禁按「有服務即重複計件」或分拆整案金額。
  - 一般訂單須有有效已發生工作日才認列開案；服務開始前整案換人由開案實際執行第一節段主責者認列；主責 lineage 不完整或歧義時 fail closed。
  - 歷史服務中、服務完成與帳務完成訂單如有有效正式工作日，沿用正式排班認列。其餘依[歷史訂單採納證據](27_歷史訂單生命週期與服務天數帳務正式規格.md)與有效指派確認開案當日的唯一主責月嫂。符合條件的訂單納入實際開案月及年份選單；整案金額依 `STAFF-PERF-03` 取值。
  - **工時獨立計算**。正式排班依各月嫂於查詢期間內的有效工作日數 × `Orders.service_hours_per_day` 累計。以歷史指派認列且有每日時數的案件，依有效指派起訖與登記週休方式估算各月工作日，並優先按已確認各人服務天數校正分配。未確認各人天數時，按各人候選日分配原登記整案天數。週休不明時按日曆日分配，未登記服務天數時採候選日數。推算日數與採用天數不一致時仍列估算，保持估算總工時等於採用服務天數 × 每日時數。服務月嫂人數及年份選單涵蓋歷史估算期間；季／年工時與逐月相加一致。估算僅供報表使用。
- **`STAFF-PERF-03` 整案總額 `T` 計算**：取 [`04_Client_Finance_Domain.md`](04_Client_Finance_Domain.md) Reporting 唯讀計價投影（服務費＋樓層費／其他有效費用），不以實繳現金、補助扣抵後餘額或月嫂薪資替代。開始前取消不計件；開始後中止計 1 件並反映取消後有效 `T` 與已確認工作日。實際開始日更正後認列月份隨之移動；計價更正回到原開案月份重算更新。缺金額僅於開案應認列月顯示 `null`，不污染非認列月份之 `0`。

### 6.2 契約與呈現規定（`STAFF-PERF-04`～`05`）

- **介面結構**：保留四項期間摘要、三指標切換排行榜（前 5 名，同值同名次，僅含已知正值；後續服務者接案 `0` 仍可列工時榜）、一律按月列出之期間趨勢（月查詢即顯示單月一列）、可排序比較表與個人明細抽屜；下拉篩選變更時立即清空舊結果／舊明細／舊匯出狀態，嚴禁 late response 覆寫新條件或額外加回說明列。前期比較基準為 `0` 或 `null` 時不顯示成長百分比。
- **公共 API 與 XLSX 匯出**：`GET /api/v1/operations-reports/staff-performance` 與 `GET /api/v1/operations-reports/staff-performance/export` 統一回傳／標示 `staff-performance.v2`。畫面與匯出標示服務工時含歷史估算。XLSX 固定輸出四張分頁：`期間摘要`（所選期間單列）、`月嫂比較`（逐人）、`服務案件`（逐人逐案，並列實際開案日、是否主責、整案總額、本期認列件數與金額、本人期間工時）、`期間趨勢`（一律逐月）。

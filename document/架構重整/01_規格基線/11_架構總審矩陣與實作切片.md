## 2. SSOT 排他檢查

- Orders 不擁有 assignment、actual hours、付款、薪資或 Alert status。
- Scheduling 不擁有 Orders Terms、Finance obligation、Payroll rate 或 lifecycle status。
- Payroll 只消費有效 assignment-owned service facts，不回寫排班。
- Client Finance 與 Staff Payables 使用不同 ledger、obligation 與 reducer；Staff payout
  完整核銷，Client refund 可逐筆部分清償並保存 remaining amount。
- Government Subsidy 獨立擁有政府對手方的 claim、ledger 與 allocation；不得抵銷 Client
  Finance 客戶應收。
- Finance Import 只擁有銀行根事實與 classification，不擁有正式 ledger／allocation。
- Anomalies 只投影 source predicate 與工作流，不是任何 Domain blocker SSOT。
- Streamlit、Excel、Alert details、legacy system map、compatibility projection 及 UI session
  state 都不是 root fact。

## 4. Concurrency／replay 統一規則

1. Query 唯讀；Preview 零寫入。
2. Apply 只接受 intent、expected version、fingerprint、actor、reason 與 idempotency key。
3. Apply 在鎖定 fresh facts 後使用 Preview 的同一 candidate builder 重算。
4. 相同 key＋相同 canonical payload 回原 receipt；相同 key＋不同 payload 固定 conflict。
5. Scheduling 依 case → ascending staff mutex → replay rows → assignments → dated occupancy
   → Finance／Payroll 的順序鎖定；鎖後 impacted set 擴張即 rollback／re-preview。
6. Batch replay 必須驗證 header、request snapshot、fingerprint、連續 child ordinals 與
   lineage；partial／malformed replay 是資料完整性 blocker。
7. 只有 `unavailable`、deadlock 或明確 transient storage error 可沿用相同 identity
   bounded retry；validation、business blocker、stale 與 identity conflict 不自動重試。

## 5. Legacy writer 退出 Gate

每個實作切片先產生 scoped writer inventory，完成後再用 SQL source scan 與 runtime tests
證明下列 target：

| 寫入類別 | 唯一 target owner | 必須退出的 legacy family |
|---|---|---|
| Orders status／dates／lifecycle | Orders | payment／Finance Import、availability lock、assignment sync、`db_service` status writers |
| assignment／schedule／locks | Scheduling | rest-date direct mutation、multi-caregiver direct SQL、assignment sync、`db_service` schedule CRUD |
| actual hours／staff obligation | Payroll | schedule generator adjustment、manual actual-hours writer、`payment_service`、monthly settlement generation |
| client obligation／ledger | Client Finance | script／UI direct writers、snapshot-as-authority、`db_service` finance updates |
| staff payout ledger／links | Staff Payables | `staff_actual_transfers`、monthly settlements、Finance Import direct updates |
| canonical bank facts／classification | Finance Import | importer／watcher SQL orchestration、other Domain staging access |
| alert occurrence／projection／workflow | Anomalies | source Domain synchronous alert writes、scanner direct source mutation |

Legacy tables與歷史事件唯讀保留；退出不代表刪除。任何尚未遷移 caller 必須固定走 typed
adapter 或明確 Gone，不能保留隱藏 fallback。

## 6. 四層 pytest closure

| 層級 | 完成證據 |
|---|---|
| Module | 純 input／output、固定案例、守恆、deterministic、typed validation；不讀 DB／clock |
| Subsystem | Preview、Apply、replay、stale、lock、partial failure、rollback、retry、typed errors |
| Domain | 隔離真實 MySQL 驗證 schema、FK、unique、row lock、append-only、完整業務場景 |
| Global | Terms／Actual Start／Cancellation／Leave／Finance Import 全鏈、雙端各自精確歸零、projector recovery、thin UI |

效能／UX 另須證明 optimistic display 不冒充 Apply 成功、payload bounded、Query
pagination、cache 與 fresh Apply 結果一致、durable job replay 安全，以及實際部署
protocol／latency evidence。

Mock PASS 不得取代 Domain／Global 的真實 MySQL 證據。Finance Import 使用真實格式 Excel
與 disposable database，不得使用正式 `union_db`。

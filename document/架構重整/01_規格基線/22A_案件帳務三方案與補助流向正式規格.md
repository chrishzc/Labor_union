- 狀態：`current-spec`

## 2. 核心不變量與公式（SSOT）

<a id="case-accounting-schemes"></a>

### 2.1 案件金額關係與資金代號（`SCHEME-AMOUNT-01`、`SCHEME-CASH-01`）

| 符號／代號 | 定義與唯一口徑 | 正式負責 owner |
|---|---|---|
| `F` | 樓層費／其他費用合計（已計入 `T` 與訂金，不再重複加計） | Orders／Client Finance |
| `T`（案件總額） | `服務費 + F`；**等於月嫂應收合計**（工會不抽成、不於 `T` 外重複加付補助） | Payroll（月嫂）／Client Finance |
| `S`（政府補助） | 本案補助金額（與工會實收 `G` 及是否設方案獨立） | Government Subsidy／Client Finance |
| `客戶應付（淨負擔）` | `T - S` | Client Finance |
| `B`（客戶應繳工會） | `訂金應繳額（含 F） + 第一期 + 第二期` | Client Finance |
| `C` | 客戶付工會（永豐存入） | Client Finance |
| `G` | 政府付工會（台新存入） | Government Subsidy |
| `P永`／`P台` | 永豐一般付月嫂／台新補助轉交月嫂（合計 `P = P永 + P台` 清償 `T`） | Staff Payables |
| `R永`／`R台` | 永豐正常退客戶／台新退客戶先墊補助（合計 `R = R永 + R台`） | Client Finance |

- **資金方向與提醒語意**：銀行核銷與款項方向嚴格對應 `receivable_from_client`（客戶存入 `C`）、`payable_to_staff`（`P永／P台` 月嫂應付）與 `payable_to_client`（`R永` 一般退款或調整；`R台` 對應 `subsidy_return` 先墊補助退還）；`subsidy_advance_due` 僅為唯讀應付／先墊提醒，不構成付款或自動核銷指令。

- **`SCHEME-AMOUNT-01／TERMS-01～03`**：客戶款與補助是同一案件總額 `T` 的資金來源；`B` 及各期金額依本案獨立繳款條款（未建列期款須經正式條款確認為 0 元始視為免繳；歷史案件依 [規格 27 §6](27_歷史訂單生命週期與服務天數帳務正式規格.md#historical-accounting-carry-forward) 承接原期款，缺漏列待確認，不虛構基準應收）。
- **`SCHEME-CASH-01` 與守恆範例**：`工會收付差額 = C + G - P永 - P台 - R永 - R台`。下為 `T = 30,000`、`S = 12,000` 的三方案完成淨額（均為實收減沖正後淨額）：

| 項目 | 方案一（分別入款） | 方案二（先墊後退） | 方案三（政府直接付客戶） |
|---|---:|---:|---:|
| `C`（永豐客戶入款） | 18,000 | 30,000 | 30,000 |
| `G`（台新政府入款） | 12,000 | 12,000 | 0 |
| `P永`（永豐付月嫂） | 18,000 | 30,000 | 30,000 |
| `P台`（台新轉交月嫂） | 12,000 | 0 | 0 |
| `R永`（永豐正常退客戶） | 0 | 0 | 0 |
| `R台`（台新退客戶先墊補助） | 0 | 12,000 | 0 |
| 工會收付差額 | 0 | 0 | 0 |

- **`SCHEME-BANK-01／02` 與 `SCHEME-SETTLE-01／02`**：銀行分類、案件方案分類與真實交易核銷分開；工會收付差額為 `0` 不能掩蓋未完成或錯付對象；方案分類本身不等於已收付或已結清。取消違約金依 [Client Finance 取消結算](04_Client_Finance_Domain.md#client-cancellation-settlement) 獨立認列，支出 `0～100` 元手續費依 [支出核銷規則](22_銀行流水匯入與帳務異常處理正式規格.md#outgoing-statement-fee-reconciliation) 處理。

### 2.2 歷史金額關係推算與三方案判斷順序（`SCHEME-CLASSIFY-01～02`）

1. 先檢查是否已有「有效人工明確保存」或「經 B 正式套用成功之銀行明細確認」來源；已有者直接使用該確認來源，不以客戶款未齊否定明細對象確認。
2. 缺乏上述正式確認來源時，先檢查 §2.3「全額補助免自備例外」；仍不適用時始於「客戶正式收款（扣沖正）已齊」且 `S > 0` 下，依既有金額關係推算：
   - `B = T - S` → 方案一（客戶與政府分別入款；各自按實際核銷獨立追蹤）
   - `B = T` 且已確認屬本案之政府款入工會 → 方案二（客戶先墊後退；實退依 `R台` 核銷）
   - `B = T` 且已確認政府直付客戶安排 → 方案三（工會不追蹤客戶實收補助）
   - `B = T` 且無 `G` 亦無直付確認、或 `S = 0`、或證據衝突 → 待確認（嚴禁由身分或查無入款猜為方案三）

<a id="full-subsidy-no-advance"></a>

### 2.3 全額補助免自備例外（`SCHEME-FULL-01～05`）

- **`SCHEME-FULL-01`（唯一條件）**：正式適用身分為 **補助市民** 或 **原住民**，且正式服務總時數 `H <= L`（`L` 取本案有效政策／人工設定上限，不固定 `120／80`，不用已計的 `min(H,L)` 代替 `L`）。身分、`H` 或 `L` 未知時留待確認；`H > L` 或一般市民回一般三方案。
- **`SCHEME-FULL-02／03`（結果）**：條件成立即自動 `S = T`、`B = 0`（訂金、第一期、第二期免繳），直接歸入「方案一全額補助免自備子情境」，補助經政府入工會後轉交月嫂 `P台`；不要求人工免自備審核、客戶實付、或先有零額期款列，不建立客戶 `R台`。
- **`SCHEME-FULL-04／05`（守恆與分層）**：`F` 已納入 `T` 不再作第二道門檻；`P永 + P台` 合計僅清償 `T` 而不加薪；與既有收款或人工更正衝突時明示原因而不覆寫歷史；免自備自動成立不等於人工完成階段確認，仍可獨立保存人工安排。

<a id="subsidy-flow"></a>

### 2.4 補助獨立計算、B 生效時點與預檢（`SUBSIDY-FLOW-01～06`）

- **`SUBSIDY-FLOW-01／02`**：依原補助資格、有效上限 `L`、服務量與費率優先獨立計算 `S`（來源足即顯示金額，缺值顯示待確認，非 0 不補 0），不以方案或退款單為前置。方案僅決定對象（一：月嫂、二：客戶、三：政府直付），不使 `S` 由零變正、不重算前三期、不對月嫂與客戶雙邊重複建款。
- **統一金額口徑**（客戶名冊、案件抽屜、銀行核對、每月帳務與清冊共用）：

| 統一項目 | 唯一業務含義與來源 | 顯示限制 |
|---|---|---|
| 本案補助金額 `S` | Government Subsidy 含人工更正計算額 | 未定方案亦顯示；未知與 0 分開；非已成立退款或實付 |
| 應付月嫂補助／待付 | 方案一之下 `T` 內合法應付與未付餘額（Payroll／Staff Payables） | `P永 + P台` 不超過 `T`；未建單時標待成立，不以 `S` 作加薪 |
| 應退客戶補助／待退 | 方案二依 Client Finance 墊款來源成立之退款與餘額 | 與 `S` 分開；未成立／缺件明確標示，不誤顯為 0 元已結清 |
| 銀行原始實付 | 銀行列不可變 `debit` 原額 | 未核銷原列不計已清償，不用以重算 `S` |
| 已核銷金額 | owner 正式 allocation 清償額（含合法 `0～100` 手續費） | 例：應付 `12,000`、實付 `11,970`、手續費 `30` → 核銷清償 `12,000` |
| 方案三政府直付 | 本案 `S` 及政府直付客戶確認安排 | 本補助不列工會待退款、不追蹤政府實收、顯示不適用 |

- **`SUBSIDY-FLOW-03／04`（B 方案生效時點）**：原始明細保存／預覽僅產生「依明細可確認方案一／二」候選，零寫入、不移出進行中案件、不建款、不核銷；**唯有使用者觸發原「套用／確認處理（B）」重讀通過預檢計畫並提交成功，或經人工明確保存後，始正式確認方案並於同一 outer UoW 由原 owner 承接合法款項及核銷（不要求再人工重選方案）**。

#### 銀行明細判定表（一般與歷史訂單共用）

| 明細類型 | 允許的原列證據與案件／對象確認條件 | B 套用後作用 | 不足或衝突 |
|---|---|---|---|
| 永豐存入 `C` | 「銷帳編號」完整 14 碼虛擬帳號經 Client Finance 定位唯一案件與客戶 | 確認入款與墊款證據；單筆收齊或 `B = T - S` 不直接冒充明細確認方案 | 缺／不唯一保留待確認 |
| 永豐出款 `P永` | 戶名／備註／交易參考姓名或完整帳號唯一對應月嫂＋合法案件關聯（多來源須同案同人） | 確認一般月嫂付款對象（`P永` 非 `P台`，不單憑付月嫂判方案一） | 缺義務仍可驗身分；矛盾則阻擋 |
| 永豐退款 `R永` | 合法姓名／帳號與客戶／案件關聯（保留帳號與快照驗證，六碼僅限案件） | 確認一般客戶退款（`R永` 非 `R台`） | 缺正式款項前不直接核銷 |
| 台新存入 `G` | 備註「新竹市政府／新竹市府」等政府標記 | 確認政府整期來源（不拆案或替單案選方案） | 缺整期分配不偽拆 |
| 台新轉交 `P台` | 原始備註唯一月嫂姓名＋案件／指派同案關聯（若有六碼須一致）＋明確補助語意或同案正式補助印證。僅有姓名線索時依[同月配對規則](22_銀行流水匯入與帳務異常處理正式規格.md#taishin-staff-case-match)定位或人工選案（不要求六碼、交易帳號或主要帳戶） | 案件、對象及補助語意成立即依明細確認方案一（預檢 `T` 內未付與分配） | 僅有薪資字樣或同名時阻擋；不改作 `R台` |
| 台新退補助 `R台`（未定方案） | 原始備註唯一六碼定位案件／客戶＋明確客戶／雇主補助返還語意＋無月嫂姓名等相反證據（如 `ＨＣ１１５０９３雇主補助款`；不要求客戶姓名／帳號／快照） | 確認對象與方案二（先墊資格、實收與未退於建款／核銷預檢另驗） | 僅六碼僅定案件；不從未命中月嫂反推客戶 |
| 台新 `R台`（已有方案二與退款單） | 重讀備註唯一六碼定位所選案件，排除命中月嫂姓名；不額外要求帳號快照或重估方案 | 核銷既有同案補助退款 | 跨案／六碼不唯一／衝突則阻擋 |
| 台新政府退回支出 | 政府來源標記＋支出方向 | 指定原期間或政府差額（[Government Subsidy](14_Government_Subsidy_Domain.md)） | 不作 `P台／R台` 或套 100 元手續費 |
| 方案三直付 | 人工明確確認直付安排（不從查無銀行列推定） | 不立工會退款，不追客戶實收 | 不要求客戶收據證明 |

- **`SUBSIDY-FLOW-05／06`（套用前四層預檢）**：(1) **金額與來源**（計算 `S／T`、已收退與日期，歷史訂單讀原合法帳務來源不要求逐日排班，未到成立時點明示原因） → (2) **案件與對象**（依上表驗證案件與受款人，台新月嫂補助允許同月多案經人工選定一案） → (3) **擬建／沿用款項**（原 owner 產生零寫入計畫，排除重複建款與 `T` 外給付，無既存目標不阻止預檢） → (4) **接續核銷**（用該計畫檢驗月份、金額、0～100 手續費與來源資格；Apply 同單一 outer UoW 執行，同命令前序建款之版本變化不判定自我 stale）。

## 3. 公開契約：未來預設與逐案直付安排（`SCHEME-REPORT`、`finance_case_arrangement_events`）

- **`SCHEME-REPORT-01／02`、`SCHEME-DIRECT-01`**：除 §2.3 全額免自備外，預設以方案三（政府直接付客戶）為主；後續對政府提出之補助清單統一採方案三報表格式，不改寫既有方案歷史金流、亦不作為已撥款或免核銷依據。
- **逐案直付安排保存與更正（`GET／POST /api/v1/finance-import/cases/{case_no}/accounting/arrangement`）**：
  - Owner：Finance Import statement-workspace；資料表 `finance_case_arrangement_events`（append-only，`confirm_direct | withdraw_direct`、`case_no`、連續 `version`、`actor`、`reason`、`created_at`、唯一 `operation_key`）。
  - 限制：§2.3 全額補助案件初次不接受確認方案三；初次確認須各期已收齊、`B = T`、`S > 0` 且無 `G／P台／R台`；變更採 `withdraw_direct` 追加事件（均必填 `reason`，UTC offset ISO 存儲、Asia/Taipei 顯示；`expected_version` 與 `Idempotency-Key` 防 stale 409 與重送）；後續出現衝突 `G／P台／R台` 時保留原安排與歷史事件、回報方案衝突待確認。

## 4. 驗收標準

1. **`SCHEME-A01～A16`**：涵蓋 `T = 服務費 + F = 月嫂應收`、三方案金額關係推算、待確認條件（禁止缺 `G` 猜方案三）、方案三無待退款與不追蹤實收、銀行對帳 `P永／P台／R永／R台` 嚴格分離與守恆、`SCHEME-FULL` 之 `H < L`／`H = L`／`H > L`／缺值與衝突檢核、以及清單格式獨立於實際金流。
2. **`SUBSIDY-FLOW-A01～A17`**：涵蓋一般與歷史訂單先算 `S`、明細保存／預覽不生效直到 B 正式套用成功、尚無資料庫目標時之擬建款＋核銷四層預檢、`P永／R永／P台／R台` 原判定表與帳號例外區分、`應付 12,000／實付 11,970／費用 30／核銷 12,000` 統一呈現、先設方案後匯入與先匯入後設方案雙向流程，以及失敗全批回滾。

# 服務方式自訂排休

狀態：completed。78 項 backend focused tests、34 項 frontend focused tests、TypeScript 與架構 closure 通過；實際桌面／手機 UI 和 localhost development MySQL before／after 驗收 PASS。未部署。

Authority：2026-10-13 最新人工確認：排班時顯示原始匯入服務方式，人工勾選休假星期後日曆立即反應；星期只是當次試算條件，不新增保存欄位。人工確認後只保存正式服務日期。使用者已要求繼續實作與實際 UI 測試。

## 範圍與 owner

- 原始 HCM 服務方式文字不轉換、不因格式警示清空；Case Import immutable source snapshot 保留原文。
- Orders calendar detail 提供原始文字供對照。未知文字不推定固定週休；已知舊案件的既有規則保持適用。
- 排班畫面勾選 0–6 個休假星期，立刻以既有 Scheduling server 精算更新建議日曆；無固定週休須明確選擇。7 天全休拒絕，變更即廢止舊預覽，遲到回應不得覆蓋最新選擇。
- `custom_rest_weekdays` 只留在元件當次狀態及計算 request；不進 Client／Orders root、DB schema、服務日期保存 command、receipt 或持久草稿。
- Orders 沿用既有服務日期 Query／Preview／Apply，人工確認前零寫入，確認後只保存實際選定日期。既有正式重排候選不一致時沿既有流程拒絕，不能靜默改成另一組日期。
- 可選日期範圍涵蓋每週至少一個服務日及原有假日緩衝，支持 6 天固定休假。

## 驗收

1. `無休`、`休五、日` 與既有別名原文保留並可在排班畫面看到。
2. 勾選週五、週日後建議日曆立即更新，仍符合契約服務天數；未確認不寫入。
3. 變更星期後舊預覽失效，遲到計算無法覆蓋新選擇；7 天全休不能確認。
4. 人工確認保存的服務日期符合畫面，重新開啟只回讀正式日期，不恢復星期選項。
5. 桌面／手機實際網站與本機開發 API／DB 測試通過。

## 效果上限與驗證

不涉及 migration、schema、系統 seed、backfill、reset、replacement、entry switch、production 或 provider。先前的新增欄位及 migration 規劃已撤回，先前自動審查拒絕的 DB 升級計畫不再是本案需要的動作。

只使用本機 development 既有 owner writer 建立專屬合成 UI 驗收案件；保存 before／after 與既有 receipt，不改其他案件。驗證 HCM 原文、calendar typed query、server 星期精算、React 變更／race／確認保存及實際 UI。必要 acceptance 通過後關閉，部署另需授權。

# 未實作、未落地、未上線規格總表

## 1. 用途與判定規則

本表是 2026-08-11 的現況盤點快照。它只整理已人工確認的正式規格，並把三種常被混用的狀態分開：

| 狀態 | 定義 |
|---|---|
| 未實作 | 已核准的業務／技術契約尚沒有可接受的 production-code、schema 與驗收鏈。 |
| 已實作未落地 | 有局部成果，但尚未達 Work Package 的全部 acceptance；不得對外宣稱可用。 |
| 已驗證未上線 | 已完成核准 scope 的實作與驗證，但尚未對任何 production target 執行部署／schema apply。 |
| 刻意不自動化 | 規格明定只建立待辦、退款單或 anomaly；不產生付款、扣款或自動結清。這不是缺口。 |

「上線」僅指已取得實際 target 的 release execution record，並完成該 target 的 schema／application release 證據；本表不把本機、validation schema 或 disposable MySQL 當成 production。

## 5. 收斂後的工作順序

1. WP56 已完成 closeout；production deployment、正式 LINE 與 cutover 仍由正式規格 18 的獨立 release execution record 管理，不回填為 WP56 缺口。
2. 對 Legacy／MySQL adapter 的待授權承諾另立不重疊 Work Package；LINE provisional registration 的 Case Import consume／merge residual 已完成，不再建立新的 provisional registration backlog。
3. Finance Amendment 如要上線，由指定 operator 為目標環境填寫 WP 57 execution record，執行核准的 additive release，並寫入結果 receipt；不得由本機測試替代。
4. 全系統要宣稱「已上線」時，依正式規格 18 建立可追溯的 release state／manifest／switch receipt。此為 release 證據工作，不表示另加一份冗長的 production migration procedure。

## 6. 維護規則

- WP 56 完成時，移出 §2 並在該 Work Package 連結 acceptance evidence。
- 任一 release 實際執行後，更新 §3 的 target、revision、schema digest 與 receipt 連結；沒有這些資料不得改標已上線。
- 新增功能只有在正式規格與已核准 Work Package 產生後，才能加入 §2；提案、來源稿與歷史文件仍留在 §4。

## 2. 正式匯入操作

先使用 dry-run；完整結果寫到檔案，終端只顯示短摘要：

```powershell
.venv\Scripts\python.exe scripts\imports\import_finance_excel.py `
  --dry-run `
  --excel-path "C:\完整路徑\歷史對帳單.xlsx" `
  --report-path "C:\完整路徑\finance-import-dry-run.json"
```

確認短摘要、報告、DB identity、筆數及分類分布正確後，正式匯入時移除
`--dry-run`：

```powershell
.venv\Scripts\python.exe scripts\imports\import_finance_excel.py `
  --excel-path "C:\完整路徑\歷史對帳單.xlsx" `
  --report-path "C:\完整路徑\finance-import-apply.json"
```

注意：

- `--excel-path` 必須包含實際副檔名，例如 `.xlsx`。
- 歷史格式只讀契約允許的欄位範圍，不把第 12 欄比對欄位、姓名或備註當成
  銷帳編號。
- dry-run 走完整 transaction 後 rollback，不應留下 batch、row、occurrence、
  正式交易或 system alert。
- 正式匯入預設會寫入 DB；不得為了重跑而刪除整個資料庫。

## 3. 既有 batch 重處理

既有 staging batch 必須先 dry-run：

```powershell
.venv\Scripts\python.exe scripts\imports\reprocess_finance_import_batch.py `
  --batch-id 1 `
  --report-path "C:\完整路徑\finance-reprocess-batch-1-dry-run.json"
```

保存輸出的 64 碼 `plan_fingerprint`。人工核對後，只有同一 DB、同一 batch、
同一資料狀態才可 apply：

```powershell
.venv\Scripts\python.exe scripts\imports\reprocess_finance_import_batch.py `
  --batch-id 1 `
  --apply `
  --actor "operator-name" `
  --plan-fingerprint "<dry-run 輸出的 64 碼 fingerprint>" `
  --report-path "C:\完整路徑\finance-reprocess-batch-1-apply.json"
```

Apply 前必須先確認：

- additive schema `db/schema_parts/61_finance_import_reprocessing.sql` 已由正式
  migration 流程套用；不得使用會重建資料庫的 `scripts/init_db.py`。
- batch 狀態為 `completed`，DB server/database 與 dry-run 相同。
- selected/changed/remaining、方向與原因分布符合人工預期。
- `plan_fingerprint` 沒有 stale；不使用 force、姓名匹配或刪除資料繞過門禁。

## 4. `IMPORT-006` 警示

無法分類的歷史流水顯示於：

`異常警示中心 → 資料匯入異常`

每個 batch 只物化一筆 `IMPORT-006`，一般頁面只讀 `system_alerts`，不在每次
API request 重算全部銀行流水。重處理後仍有 review rows 時更新或 reopen；
剩餘數歸零時自動 resolve。

## 5. 驗收與稽核重點

正式 apply 後至少核對：

1. `finance_import_batches`、`finance_import_rows`、
   `finance_import_occurrences` 的 cardinality 符合報告。
2. canonical row 沒有因改檔名、sheet 或列號而重複建立。
3. `finance_import_reprocess_runs` 記錄本次 run；
   `finance_import_reclassification_events` 數量等於真正 changed rows。
4. 正式交易能追溯 `finance_import_row_id`，exact replay 不重複寫入。
5. 未分類 rows 仍為 `non_business_review`，並由單一 `IMPORT-006` 彙總。
6. 報告與警示不得保存姓名、完整帳號或 raw payload。

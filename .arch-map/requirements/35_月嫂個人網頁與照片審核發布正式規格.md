# 月嫂個人網頁與照片審核發布正式規格

## 1. 文件邊界與所有權

- 狀態：`current-spec`
- Owner：Staff Domain／個人網頁與內容發布 Subsystem。
- 單一負責範圍：月嫂個人網頁共用模板、各類圖片送審及管理員代傳、後台審核與手動發布、目前照片關聯的移除、客戶可見內容及其他類別項目到期提醒的業務規則。
- 關聯引用：見 [Global 共同契約](00_Global_共同契約.md)、[LINE 自助服務](20_LINE客服與月嫂自助服務正式規格.md#月嫂更新個人資料)、[媒合客戶確認](02A_媒合候選池與客戶決定及通勤規格.md#32-客戶推薦確認手動更正與服務前整案換人r-04)、[通知投遞與文案](17A_LINE_Gateway_Inbox與通知投遞正式規格.md)、[受控檔案儲存](30_Controlled_File_Storage_NAS正式規格.md)、[管理端名冊](33_案件與月嫂整合名冊正式規格.md#42-月嫂名冊與公會編號)。

姓名仍由 Staff Profile 擁有，檔案 bytes 與檔案版本由受控檔案邊界管理；本 Subsystem 擁有模板項目、月嫂內容與項目的關聯、審核結果、發布版本及提醒設定。媒合、LINE 與管理端只消費各 owner 的 typed 結果，不另存一份姓名或重定義發布資格。證照照片與提醒日期不改寫專業資格、可接案條件或 Scheduling 規則。

## 2. 核心不變量與資料模型

### 2.1 共用模板與項目（`STAFF-WEB-01`）

- 後台管理一套供月嫂個人網頁共用的模板，管理員可新增項目及調整項目名稱與顯示順序。每個項目必須選擇一個類別；項目可持續擴充，類別固定為下表四種。

| 類別 | 到期日要求 | 到期提醒 |
|---|---|---|
| 照片 | 不會到期，不要求到期日 | 不啟用 |
| 證照 | 不會到期，不要求到期日 | 不啟用 |
| 其他 | 必填到期日 | 後台可設定是否啟用 |
| 客戶反饋 | 不會到期，不要求到期日 | 不啟用 |

- 是否需要到期日由類別決定，不提供項目自行覆寫此規則的開關。提醒只適用於「其他」類別；變更為照片、證照或客戶反饋時，不得繼續要求日期或啟用到期提醒。
- 每筆上傳內容歸屬指定月嫂及一個模板項目，保留照片檔案關聯；其他類別的內容另保存到期日。月嫂只能為本人送件，管理員可依授權為指定月嫂代傳。上傳及送件操作不得自行新增模板項目、更改類別或共用提醒規則；模板管理另依[後台模板管理](#31-後台模板管理)辦理。

### 2.2 送審內容與發布版本（`STAFF-WEB-02`）

- 月嫂上傳或更換照片後先形成待審內容。待審照片及日期不得直接成為客戶可見資料，也不得因檔案上傳成功自動發布。
- 工會人員在後台核對項目與照片，並依類別核對必要日期，審核後手動發布。核准與發布可由同一次人工操作完成；系統必須能讀回實際發布結果。
- 工會人員可在審核時裁切待審照片，查看原圖與裁切結果後套用。裁切保留原始檔案與來源關聯，僅形成待審版本；取消裁切或退回不更新已發布內容，審核發布成功後才提供裁切後的完整圖片。
- 新照片待審、退回或發布失敗時，客戶繼續看到原本已發布的內容。只有新照片審核並發布成功，才取代對應的已發布照片。
- 客戶查詢及照片讀取只能取得已發布版本。不得透過待審檔案連結或未經審核的上傳結果取得待審照片。
- 發布沿用 owner version 與 fresh-read 驗證；無權限、來源已變更或版本衝突時不更新客戶可見內容，並回報明確失敗或 typed conflict。查詢與預覽不發布內容或發送訊息。

### 2.3 客戶個人網頁（`STAFF-WEB-03`）

- 對客戶提供月嫂資訊時，提供該月嫂的個人網頁連結，取代履歷 PDF、PDF 下載或 PDF 轉圖片的履歷呈現方式。
- 網頁呈現姓名與已審核發布的圖片，固定依「照片、證照、其他、客戶反饋」順序分成最多四列。每列顯示類別標題及圖片，單張圖片不顯示模板項目名稱。同類別的各模板項目合併在同一列，依後台項目順序排列，不因新增項目增加直向列數。個人文字資料先限姓名，不自行加入電話、地址、銀行帳戶、身分證、學經歷或其他個資欄位。
- 每個類別的圖片保持同一橫列，多張可左右滑動，不向下換行。客戶端依比例完整呈現已發布的圖片，不自行裁切；後台已裁切發布者顯示該完整裁切結果。
- 沒有已發布圖片的項目不佔圖片位置。整個類別皆沒有已發布圖片時，連同該類別標題一併隱藏。待審內容不顯示，也不佔圖片位置。
- 姓名讀取 Staff Profile 的正式資料；各類圖片只讀本 Subsystem 的已發布內容，不讀月嫂待審資料。
- 到期日只供提醒月嫂使用，不在客戶網頁顯示到期日或「已過期」標記。其他類別的內容到期後持續顯示原照片，直到新的照片完成審核發布後取代，或管理員依 [STAFF-WEB-05](#25-後台檔案管理staff-web-05) 明確刪除目前內容；不因到期自動隱藏或下架。
- 對客戶的網頁與照片讀取依既有授權邊界提供必要欄位，不暴露內部管理查詢、待審內容、實體儲存路徑或原始個資。

### 2.4 到期提醒（`STAFF-WEB-04`）

- 到期提醒的收件人為該月嫂本人，透過其有效綁定的 LINE 私聊提醒即將到期。僅其他類別且已啟用提醒的項目符合資格，照片、證照、客戶反饋及未開啟提醒的項目不發送到期提醒。
- 預設提前一個月提醒；管理員可在後台調整提前時間，不能將「一個月」逕自寫死為不可調整的天數。
- 提醒訊息模板可由後台調整，文案維護與投遞沿用[通知文案與投遞契約](17A_LINE_Gateway_Inbox與通知投遞正式規格.md#5-rich-menu通知文案編輯與表格圖片)。
- 提醒以目前有效的已發布內容之到期日及目前有效設定為依據；已移除內容不產生後續提醒。新照片仍待審時不以待審日期取代原提醒依據；新內容發布後依新日期處理後續提醒。
- 提醒排程與投遞沿用既有 committed 工作、防重送及失敗回讀機制。調整設定、編輯訊息或查看預覽本身不直接發送提醒。提醒與否不改變客戶網頁的發布狀態。

### 2.5 後台檔案管理（`STAFF-WEB-05`）

- 共用模板下，每位月嫂的檔案各自管理。以 `staff_id` 與 `template_item_id` 識別人員與項目的分組，項目名稱不是識別依據。資料夾是管理分組，不代表實體檔案系統路徑。每位月嫂的每個「其他」項目各有專屬分組，最多一張目前已核准發布的照片；照片、證照及客戶反饋項目可有多張。
- 管理員可代傳辦公室已留存的歷史照片，不要求月嫂重新送件。代傳與 LIFF 使用同一套模板、受控檔案 owner 及正式發布內容，不建立另一份資料來源或假冒 LINE 身分。確認發布是人工核對與發布動作，須通過檔案驗證、授權、fresh version 與既有 writer；發布成功並回讀後更新客戶頁，失敗時保留原內容。
- 管理員可明確確認刪除選定人員、項目及檔案的目前內容關聯。取消不改變資料；內容變更、失去權限或版本過期時以 typed 拒絕，不影響其他人或其他檔案。成功後目前清單與客戶頁不再顯示該照片，張數更新；資料夾及模板保留，可再次代傳。空項目及空類別依 [STAFF-WEB-03](#23-客戶個人網頁staff-web-03) 隱藏。
- 刪除目前內容關聯不授權直接刪除實體 bytes、frozen 版本、證據或來源脈絡。檔案及版本保存依[受控檔案儲存](30_Controlled_File_Storage_NAS正式規格.md)。

## 3. 公開契約與流程

### 3.1 後台模板管理

管理員新增模板項目，設定名稱、類別與同類別內的顯示順序。日期要求及可否提醒依[類別規則](#21-共用模板與項目staff-web-01)決定；其他類別可設定是否提醒，啟用時可調整提前時間及訊息模板。設定完成後，月嫂「我的資料」可選取對應項目送審。模板設定不代表任何月嫂照片已經審核或發布。

### 3.2 月嫂「我的資料」送審

月嫂從 LINE 圖文選單「我的資料」開啟本人 LIFF。沿用原本的個人資料申請，可在同一張申請更新原欄位，並對一個或多個模板項目上傳照片。照片、證照及客戶反饋項目各可上傳多張；其他類別每個項目一次只能上傳一張，同一申請可對多個其他項目各上傳一張。只更新原欄位或只送審照片都可提交。照片、證照及客戶反饋不要求日期，其他類別的每張照片必須填寫到期日。身分驗證及待審受理沿[LINE 自助服務](20_LINE客服與月嫂自助服務正式規格.md#月嫂更新個人資料)。附件沿[受控檔案儲存](30_Controlled_File_Storage_NAS正式規格.md)處理。其他類別同一項目上傳多張、未填日期、日期格式不合法或檔案未通過受控驗證時，回報原因，整張申請不進入待審。

### 3.3 後台審核與手動發布

管理員開啟待審資料，核對項目、照片與該類別要求的日期後手動發布，或退回月嫂補正。月嫂可查閱本人送審狀態。客戶頁面只在發布成功後更新；未核准或操作結果未明時，不顯示發布成功。

### 3.4 提供客戶資訊

工會在推薦月嫂給客戶時，提供對應個人網頁連結。媒合確認包與接受配對流程由[媒合規格](02A_媒合候選池與客戶決定及通勤規格.md#32-客戶推薦確認手動更正與服務前整案換人r-04)擁有，不以 PDF 是否存在或轉圖片是否成功作為提供個人網頁的條件。已保存的 PDF 與寄送證據依原保存規則保留，本流程不刪除或自動轉換既存檔案。

### 3.5 管理員代傳與刪除

管理員選擇月嫂、類別、模板項目及檔案，其他類別必填到期日，照片、證照及客戶反饋不要求日期。管理員核對後確認發布，系統依 [STAFF-WEB-05](#25-後台檔案管理staff-web-05) 驗證、發布與回讀。其他類別的新圖待審、退回或發布失敗時，該人員與項目原有的發布照片仍可見；只有人工發布成功才取代目前版本。

管理員開啟所選項目的資料夾，選擇檔案並確認刪除，或取消操作。刪除及保存邊界依 [STAFF-WEB-05](#25-後台檔案管理staff-web-05)。

| STAFF-WEB-AC-07 | 其他類別已核准且啟用提醒，照片、證照及客戶反饋不會到期 | 提前提醒月嫂 | 依預設提前一個月執行提醒，再調整提前時間及文案，對適用的後續提醒執行評估 | 在設定的提前時間，以有效文案提醒該月嫂本人；照片、證照、客戶反饋及未啟用提醒者無到期提醒；設定及預覽本身不發送 |

| STAFF-WEB-AC-09 | 同類別有多個模板項目與多張照片，寶寶按摩證書尚無已發布照片，另一類別只有待審內容 | 減少客戶上下捲動 | 新增項目、調整同類別項目順序並發布照片，在電腦與手機左右滑動查看 | 新內容加入對應類別橫列，最多四列且各列不向下換行。每列顯示類別標題，圖片按模板順序完整呈現，單張圖片不顯示模板項目名稱。空項目及待審內容不佔圖片位置，沒有已發布圖片的類別整列隱藏 |

## 5. 畫面設計邊界

後台保留月嫂名冊表格及右側原詳情抽屜，不改為左右工作區或新增詳情分頁。抽屜「專業資格與服務資料」保留「履歷網頁與照片」區塊，主要動作只有「查看履歷網頁」及「代傳照片」。照片、證照、其他、客戶反饋分類以緊湊清單逐模板項目顯示名稱、張數、其他類別到期日及開啟資料夾；資料夾僅查必要 metadata，列檔名、其他類別日期及「刪除照片」，不提供預覽、新增或替換入口。代傳選檔只列檔名及張數。

抽屜、資料夾及選檔介面不顯示縮圖、不預抓圖片或轉 base64；檔案上傳與伺服器驗證仍可讀取必要 bytes。只有按「查看履歷網頁」才進入已發布頁讀圖，獨立照片審核仍可按需讀原圖與裁切。

名冊全域分頁列依序為「現役月嫂、已退役月嫂、履歷網頁」；第三分頁管理共用模板、照片審核與到期提醒，與個人抽屜入口用途不同。客戶頁的固定四類橫列、完整圖片及空白隱藏依本文契約；其餘視覺樣式另依設計討論確認。具體 API 路徑、資料表與頁面路由不在此指定。

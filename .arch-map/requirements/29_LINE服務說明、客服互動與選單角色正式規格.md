# LINE 服務說明、客服互動與選單角色正式規格

## 1. 範圍與權威邊界

本文件為 LINE 官方帳號對話入口、四大 Rich Menu 角色選單（`default_menu`／`customer_menu`／`staff_menu`／`union_staff_menu`）、預約檢核閘道（Gateway）與 聊天室常見問答之現行唯一正式規格。

- **上下游分工**：平台 Webhook 收件、投遞、舊客服工單交接與 `line_webhook_reply` 見 [`20_LINE客服與月嫂自助服務正式規格.md`](20_LINE客服與月嫂自助服務正式規格.md) 與 [`17A_LINE_Gateway_Inbox與通知投遞正式規格.md`](17A_LINE_Gateway_Inbox與通知投遞正式規格.md)；新案登記與非市民 14 天 Redis 待審儲存見 [`17B_Case_Import與非市民Redis待審正式規格.md`](17B_Case_Import與非市民Redis待審正式規格.md)；身分解除見 [`23_LINE身分管理與解除正式規格.md`](23_LINE身分管理與解除正式規格.md)。

## 2. 服務閘道（Gateway）與登記入口規則

1. **同一閘道兩步分流**。第一步顯示「新竹市民」與「非新竹市民」。第二步只顯示所選身分的兩個選項，並提供「返回選擇身分」。兩步選擇僅決定頁面導向，實際登記、身分與綁定結果由各目的地的既有流程核對。
   - **新竹市民 → 已在市府平台登記**。進入既有姓名與手機核對流程。資料完整且未綁定時完成綁定並排入選單更新。缺問卷或查無資料時，分別帶入已核對資料或姓名與手機轉入產婦問卷。核對錯誤提示修正，仍無法綁定時請到官方帳號留言。
   - **新竹市民 → 尚未在市府平台登記**。前往新竹市政府到宅月子媒合服務平台申請。
   - **非新竹市民 → 工會已建案，綁定 LINE**。手動建案及核准建案皆適用。沿用既有客戶綁定流程，以建案時的姓名與手機號碼核對。資料完整且未綁定時可完成綁定，免重填需求問卷。已綁定同一帳號時顯示已完成。需更換帳號時，依身分管理規格請工會確認身分並完成解除舊綁定，再用新 LINE 帳號綁定。查無資料、資料不完整或核對失敗時留在綁定頁，提示修正或直接在官方帳號聊天室留言。
   - **非新竹市民 → 尚未申請**。開啟非市民自費申請專用 LIFF 頁。送出後顯示「申請已送出，待工會核准」。待審、核准建案及配號依 [非市民進件與待審規格 §3](17B_Case_Import與非市民Redis待審正式規格.md#3-非市民自費進件與專用-redis-7-待審隔離架構)。
   - **待審提示**。只在非新竹市民的第二步、兩個選項下方顯示「已送出申請，還在等工會審核？請等候審核結果，無須重複填寫。」這是固定提示，顯示時無須查詢個別申請。
2. **加入好友歡迎訊息退役（改由 LINE 官方帳號設定）**：
   - 系統不對 LINE `follow` 事件開啟身分流程、排程或發送歡迎訊息，加入好友歡迎訊息改於 LINE Official Account Manager 官方後台直接設定（避免重複發送或消耗推送額度）。
   - 原系統即時歡迎詞（`customer_onboarding_welcome`）、`D+1`～`D+3` 多日延遲引導排程與歡迎詞管理 API（`/api/v1/line/onboarding`）均已退役（API 回傳 `410 Gone`，資料庫設定歷史不刪除，管理端通知清單與公版目錄不再列入）。
   - 使用者於聊天室主動輸入客戶／月嫂／工會綁定關鍵字時，仍依 `line_webhook_reply` 回覆對應身分入口連結。

## 3. 服務說明與聊天室常見問答

### 3.1 入口定位與退役頁清理

- **唯一對外問答入口**：訪客與客戶從圖文選單送出「常見問題」，LINE 在原一對一聊天室 Reply 分類卡片；選分類及題目後回當下正式答案。找不到時提示直接留言；不開啟 LIFF、不呼叫模型、不使用 Push。
- **分類導向**：原「服務流程介紹」（`service_flow`）與「費用與補助說明」（`fee_and_subsidy`）亦統一收斂為常見問題之分類卡片；費用與補助固定使用現行政策分類說明「一般市民最高 40 小時／補助市民最高 120 小時（實際補助金額依本案服務資料計算）」，烹飪備料固定明示「由客戶購買並準備食材」。
- **客戶端自助表單退役與後台維護原則**：經工會實務反饋，客戶端無線上自填改單與改個資需求，易造成版本混亂。客戶圖文選單全面移除「改個人資料」與「改訂單內容」入口，聊天室亦不再提供線上自填表單連結。客戶若有聯絡方式、服務地址或訂單需求變更，一律由客戶於官方帳號或案件群組直接留言，由工會專員於管理後台手動確認並調整。舊自填表單、送審與審核入口均已退役。
- **已退役訊息範本入口（11 個獨立範本與 `service-flow`／`service-payment` 皆回 `404`）**：`service-flow` 與 `service-payment` 之獨立查詢／預覽／編輯回傳 typed `404`（不刪除既有資料庫設定）；另以下 11 個無現行引用之 standalone 訊息範本編輯及公版預覽入口已自目錄移除並回傳 `404`：`staff_switch_fail`、`staff_menu_not_set`、`esc_success`、`esc_fail`、`bind_link_msg`、`register_success`、`bind_success_existing`、`bind_confirm_rebind`、`bind_fail_no_data`、`client_rebind_approved`、`staff_verification_requested`（bootstrap 與資料庫設定歷史不刪除，其他規則明確引用者仍沿該 rule ID 維護）。

### 3.2 舊網頁／AI 問答退役

舊 AI 指令或相容按鈕只回聊天室 FAQ 或留言指引。原公開 FAQ／AI 網頁及問答 API 退役，舊網址回 410 指引，不再顯示題庫或呼叫模型。不再提供 AI 回答測試、回饋分析及模型設定。既有歷史資料、其他 LINE 入口及正式問答版本不因退役刪除。

## 4. 可發布知識庫目錄（Knowledge Catalog）

1. **題庫來源與種子資料**：基礎題庫定義於 `document/line/AI客服QA題庫.jsonl`（54 題核心問答）。`development` 環境啟動時自動進行冪等播種並預填可檢索索引；`production` 環境維持由管理員於介面手動觸發「播種／同步」與「審核發布」，禁止未經人工確認自動覆蓋線上知識版本。
2. **檢索與 `authoritative=false` 不變量**：
   - 先進行受保護的精確別名／題庫比對，僅針對已發布版本提供即時問答。聊天室回覆格式依 §4.1。
   - 問答無法命中高信賴回答或超出題庫範圍時，不提供未核准答案，提示使用者在聊天室留言。**嚴禁聊天室自動觸發未受控自由生成回答或代行任何 Orders／Scheduling／Client 資料寫入**。
   - 嚴格區分 `author != reviewer != publisher` 發布檢核（非開發單人情境下不可由同一人越級自審自發）。

### 4.1 共用問答與聊天室版面

- 「LINE 常見問答」是唯一管理入口，保留「常見問答題庫」及「LINE 聊天室版面」。題庫維護完整題目、正式答案與同義問法；版面只維護分類、卡片文案、短標籤、順序與題目引用，不提供 AI 快捷入口。
- 編輯版面時，左欄提供「＋ 新增分類」。輸入非空且不重複的分類名稱後建立草稿，立即選中該分類並顯示空白題目清單；名稱預填為卡片標題。新增分類在同一管理介面維護，不要求工程師修改 schema、程式或 JSONL。卡片可挑選已發布的題目，每張最多四個題目按鈕，可調整順序、修改短文字或移除引用。這是現行卡片版型的上限，不是 LINE 平台上限。移除引用不會停用題目。
- 右欄手機預覽可點「分類選單 → 分類卡片 → 問答」，可切換「草稿／已發布」。預覽不推播、不發送聊天室訊息、不變更任何 Rich Menu。草稿儲存不影響對外內容；模擬或預覽不等於正式發布。發布分類版面後，才出現在正式 LINE 分類選單，不須重新發布圖文選單。發布版面不得發布、修改或停用任何題目。
- 題目正式發布後，後台受權限保護的正式讀回與聊天室舊／新按鈕都讀當下正式版。透過題目按鈕命中正式答案時，LINE 只送一則純文字訊息，文字逐字等於已發布的答案。系統不加題目、資料來源、版本、固定免責文字、留言提示或返回按鈕。管理員要顯示的提醒直接寫在答案中。手機預覽的答案泡泡也只顯示原文。
- 草稿不取代既有正式答案。停用或查無正式答案時，舊按鈕只給 FAQ 或留言指引。相容讀取可用種子資料辨識舊題目，回覆仍須取得正式答案。
- 具題庫管理權限者可在「常見問答題庫」確認永久刪除沒有生效正式答案的題目，包括從未發布的草稿、待啟用題目與已停用題目。仍有正式答案的題目須先停用，即使編輯狀態顯示草稿也一樣。成功後題目及已儲存的內容版本從題庫移除，保留最小操作識別以便稽核及避免匯入復原。舊 LINE 按鈕依查無正式答案的規則回指引。
- 服務登記、進度、資料修改、舊分類指令及發布權限沿用。來源故障不回草稿或假裝無題；聊天室提示重試或留言，管理端明示讀取失敗。

下列案例為跨角色驗收來源。為避免客服在修改常用答案時突然查不到資訊，儲存版面或問答草稿都不得改變任一對外入口；只有成功發布／停用才改正式結果。

| 情境（S） | 任務（T） | 操作（A） | 可觀察結果（R） |
|---|---|---|---|
| 分類「服務異動」不存在，題庫已有發布題 | 新增分類與卡片 | 左欄新增、選一題、切換預覽，再發布版面 | 草稿手機選單先出現該分類，已發布選單不出現；發布後重開已發布選單可點入並讀正式答案。 |
| 輸入空白或同名分類 | 防止建立無效分類 | 提交名稱 | 顯示原因，沒有新增分類或版面。 |
| 一題已被聊天室引用 | 更新答案一次 | 儲存草稿，讀回正式版，再正式發布 | 儲存期間後台讀回及聊天室都回舊正式答案；發布後都讀新版本，不重發版面。 |
| 一題有含換行及管理員自寫提醒的正式答案 | 在 LINE 查看答案 | 分別點新、舊題目按鈕，並開啟手機預覽 | 兩種 LINE 回覆都只有一則純文字訊息，文字等於已發布答案原文。預覽的答案泡泡顯示相同原文。 |
| 舊題目只存在於種子檔，題庫查無正式答案 | 查看該題 | 在切換前相容模式點舊題目按鈕 | 聊天室顯示 FAQ 或留言指引，種子答案不會送出。 |
| 已發布題超過 100 筆且部分未放卡片 | 管理員選入一題 | 開啟後台選題並翻到最後 | 有權限者可找到；未放卡片不自動顯示於分類，對外沒網頁題庫。 |
| 一題原在聊天室卡片上 | 區分移除引用與停用 | 先移除引用並發布；再停用，點舊按鈕 | 移除不會停用；停用後舊按鈕不再回原答案。 |
| 題庫有從未發布的草稿及已停用題目 | 清除不用的題目 | 分別點「永久刪除」並確認，重新整理；再匯入內建題庫 | 題目在後台查不到。已刪除的內建題目也不會重建；舊 LINE 按鈕只回指引。 |
| 題目有正式答案，或管理員開啟頁面後該題已被別人發布或更新 | 避免刪掉生效答案或新版本 | 以畫面原先讀到的版本提交刪除 | 系統拒絕刪除，題目與最新版本仍可讀取。有生效答案時，LINE 仍回該正式答案。 |

補充例外：兩位管理員同時編輯時，持有過期 revision 的命令不得覆蓋目前版本；重送同一次發布不得再發一版。只有完成正式回讀才告知使用者已發布。FAQ 內容不是個案資料，舊按鈕或無效分類不得變成查詢、修改個案的入口。新增空白分類可先存草稿，至少選入一筆仍已發布的問答才能對外發布。若正式題目仍有未發布修訂，停用仍應讓現在的正式答案下架，不須先發布修訂。

版面與接線由 [LINE FAQ 聊天室版面架構](../domains/external-integration/subsystems/line/modules/faq-chat-layout.md) 說明；題庫權威由 [可發布問答目錄架構](../domains/knowledge-retrieval/subsystems/knowledge-retrieval/modules/reviewable-qa-catalog.md) 說明。

## 5. 四大角色圖文選單（Rich Menu Audiences）

為符合高齡友善操作與直觀辨識，訪客、月嫂與工會選單統一採用 **`2500 x 1686` 高對比大字體規範**（主標字級 `138px`／副標或輔助說明 `48px`）；**客戶選單（`customer_menu`）採用半高 `2500 x 843` 雙格設計**，左格為「案件資訊」（查詢已確認之服務條件與費用約定），右格為「常見問題」（即時 FAQ 導覽卡片），簡潔且不遮擋聊天對話。**按鈕標籤一律壓縮至 6 個中文字以內**。四套選單與切換條件如下：

| 選單 ID | 適用身分（Role Context） | 按鈕固定標籤（≤ 6 字） | 動作／導向契約 |
|---|---|---|---|
| `default_menu` | `visitor`（未綁定訪客／待審新客） | `預約與登記`、`月嫂認證`、`常見問題` | 預約與登記 → Gateway LIFF；月嫂認證 → `staff_binding` LIFF；常見問題 → 訊息 `常見問題`（觸發聊天室即時常見問題導覽卡片與 Quick Reply 懸浮分類） |
| `customer_menu` | `customer`（已綁定正式產婦／客戶） | `案件資訊`、`常見問題`（半高 `2500 x 843` 雙格） | 案件資訊 → postback `customer:case-information`（以原生 Flex 卡片即時回傳服務約定、客戶付款約定與其他約定；未綁定或無案件時給予引導）；常見問題 → 訊息 `常見問題`（觸發聊天室即時常見問題導覽卡片與 Quick Reply 懸浮分類）；客戶端不提供線上自填改個資或改訂單表單，若需異動請直接在聊天室留言由工會人員於後台編輯 |
| `staff_menu` | `staff`（已綁定在職月嫂） | `我的訂單`、`我的排班`、`我的資料`、`我的薪資` | 我的訂單 → `staff_order_search` LIFF；我的排班 → `staff_schedule` LIFF；我的資料 → [月嫂更新個人資料](20_LINE客服與月嫂自助服務正式規格.md#月嫂更新個人資料)；我的薪資 → `staff_payout` LIFF |
| `union_staff_menu` | `union_staff`（已綁定工會後台人員） | `待辦工作台`、`狀態追蹤`、`營運摘要` | 分別開啟 `line-mobile-admin` 對應視圖：`staff_review`、`order_tracking`、`dashboard` |

- **雙角色、結案回復與月嫂退役**依 [LINE 身分管理與解除規格](23_LINE身分管理與解除正式規格.md) 的角色選擇及回復流程。
- **工會選單退役路由防呆**：`union_staff` 端原 `anomalies_center` 選單路徑自動重導至 `order_tracking`；`dashboard` 只消費經 server 遮罩且符合 [`34_營運報表與統計口徑正式規格.md`](34_營運報表與統計口徑正式規格.md) 口徑之本週營運摘要（`WeeklyOperationsReportQuery`／`operations-report.v4` 相容彙總），不揭露客戶或員工明碼個資。

## 6. 官方聊天室客服互動與狀態一致規則

1. 官方一對一聊天室的一般詢問與正式客訴由工會直接查看與回覆。系統只對明確的自助指令提供對應服務。
2. 訪客與工會選單採三個按鈕，月嫂選單採四個按鈕，客戶選單採左右雙按鈕「案件資訊」與「常見問題」。舊「聯絡專人」回原聊天室的直接留言指引，舊手機客服中心連結開啟待辦工作台。
